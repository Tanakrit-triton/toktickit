## 3. My Reflection

**What the agents did well.** The most useful thing the AI did this sprint was stop instead of guessing. I wrote and approved the Sprint 4 contract, yet the coding agent found eight places where it contradicted itself or left a gap. One example is Amendment 1: the same action edit returned two different error codes depending on which section was read. Another is Amendment 7: two dashboard cards linked to lists that could never match their counts. This is the same lesson as Lab 2: specification problems show up when you implement, not when you review. The agent also caught my own mistake when my prompt asked it to combine #74 and #75 into one PR, which broke the "one Issue, one PR" rule in CLAUDE.md.

**Where I had to correct it.** The agent's tests were not always trustworthy on the first try. It wrote a concurrency test (WF-08) that required both commit orders to happen. That would have made the test flaky. It also let the rollback test skip itself when the script was missing, instead of failing. It proposed reinstalling Lab 3 in a temp folder on every test run to prove the rollback, and I chose a lighter schema comparison. When E2E-09 failed, it described the Assign race as something a real user could not hit, which was not true, so I had it recorded as a known limitation instead. These were not syntax errors. They were judgment calls that looked reasonable, which is why reviewing every commit mattered even when it was slow.

**What each kind of test caught.** No single layer was enough. The E2E suite caught a bug that every unit and component test passed. After a save, the buttons re-enabled before the new version arrived, so a fast user was told someone else had changed the ticket when they had changed it themselves. Opening the screens in a real browser caught "Sept" and "01 Sep", which every test missed because they all used 29 October. STY-03, run in a browser, found two non-token colours that jsdom could not see.

**What I would do differently.** I planned more than two days could hold, and lost time early. Next time I would scope the contract to the time available and decide file ownership before running agents in parallel, not after. I would keep the habit of reading every diff and asking the agent to prove a test fails for the right reason, because that is where most of the real problems were found.
